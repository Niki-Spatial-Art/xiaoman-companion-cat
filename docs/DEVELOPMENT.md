# 开发与验证计划

当前已有前期产品方案、外观与使用情景探索，正在进行设计深化和原型准备。以下为参赛原型的实施安排，实际硬件型号、接口与测试结果随进展更新。

## 首版范围

| 模块 | 目标行为 |
| --- | --- |
| 触摸 | 摸头触发本地呼噜或微动作 |
| 微光 | 猫爪操作与一处局部暖光联调，可调亮度与关闭 |
| 语音 | 按猫爪进入说话，完成简短普通话对话 |
| 上海话试点 | 跑一组明确场景，记录识别与回复表现 |
| 提醒 | 复述、确认、计时、触发、按钮确认与记录 |
| 形态 | 柔软接触区、稳定摆放、声音与动作协调 |

## 实现分工

RDK 运行设备交互与任务状态，连接传感器、按钮、音频与动作机构。语音服务返回识别文字和合成音频，对话模型提取意图并生成简短回复。

提醒采用可检查的状态流：待复述 → 待确认 → 已设置 → 已触发 → 已确认；取消与修改进入明确分支。SQLite 保存任务与确认记录，网页展示对应状态。

呼噜、固定回应和已建立的提醒在本地执行。云端不可用时提示当前状态，交互恢复后再接续新对话。断电重启后的任务恢复列入实装设计与验证。

## 物料草案

| 物料 | 用途与选择条件 |
| --- | --- |
| RDK 开发板、电源 | 根据赛事实际提供型号配置 |
| 麦克风、扬声器 | 先验证采录和播放，关注电视声、播放回声与远近距离 |
| 压力或触摸传感器 | 头部触摸，须在柔软包覆后重新校准 |
| 实体按钮 | 猫爪位置，明确触发、停止、确认等状态行为 |
| 暖白或琥珀LED与扩散层 | 硅胶下局部微光，验证亮度、透光与触点反馈 |
| 舵机与匹配驱动（选配） | 头或尾的微动作，关注噪声与供电 |
| 内部支架与柔软包覆 | 原型装配，硅胶先制作局部小样 |

带回声消除能力的音频硬件可优先比较；语音分段与回声消除分别处理。hobot_audio 示例板卡和麦克风与实际物料匹配后再接入。

## 三天安排

| 阶段 | 工作与交付 |
| --- | --- |
| 赛前准备 | 明确分工、核对硬件、整理流程草图、准备语音样本和造型方案；记录已有基础 |
| 第一天 | 音频输入输出、触摸和按钮跑通，完成基础形态及呼噜回应 |
| 第二天 | 接入对话与提醒，比较上海话样本，联调声音与动作 |
| 第三天 | 重复演示与修复，录制视频，整理作品介绍、实际结果和 AI 辅助开发记录 |

声源转头、回忆话题和兴趣偏好依进度选择扩展。硅胶整壳、家属端和复杂机构在原型验证后推进。

鲜彩围兜、露耳帽与像素杯垫在赛后先做小样，再与养老机构或社区手工坊探索共创。阶段记录包括图样、材料、穿脱、清洁、触点与声音表现，以及参与者偏好。

## 验证计划

### 语音与方言

计划邀请 3—5 位自愿参与的沪语使用者，每人 10 句，覆盖家常、数字、提醒与混说。对比至少两种识别配置，记录关键意图、时间是否正确、澄清次数和回复等待时间。

安静近距离、约 1 米距离和电视背景声分别记录表现。记录参与者的年龄范围与沪语使用习惯，报告样本覆盖范围。声音试听评价清晰度、自然度和亲切感。

### 触摸与流程

- 比较两种柔软包覆材质，收集触感、清洁和反馈自然度评价。
- 观察体验者能否找到触摸区、开始说话、确认提醒。
- 核心提醒流程连续完成三次，核对事项、时间和按钮确认记录。
- 检查设备播放时的回声与舵机动作时的采音影响。
- 断网后验证本地触摸和已有提醒，并检查恢复联网后的状态。

## 团队方向

拟组成 2—3 人团队。发起者负责产品与交互、形态建模、体验测试和展示；技术伙伴协作完成 RDK、音频与动作控制、语音服务和提醒程序。具体职责由团队按实际能力共同确定。
